# company-desktop（Mac）

Mac 客户端自带 Peekaboo。它操作的是员工这台 Mac 上的桌面软件。网页仍然用 OpenCLI（见 `company-web`），命令仍然用自己的 shell。

## 1. 第一次用：先查权限

先调 `mcp__mac__permissions`。它会列出「屏幕录制」「辅助功能」是否已开，以及要开给哪个应用。缺了就带员工开，每次只说一步，等员工说做完了再说下一步：

1. 打开「系统设置 → 隐私与安全性 → 辅助功能」，把权限结果里写的那个应用（通常是 TDHarness 或 peekaboo）的开关打开；列表里没有就点左下角「+」添加。
2. 同一页往下找「屏幕录制」（新系统叫「屏幕与系统录音」），同样打开。
3. 系统提示「需要退出并重新打开」时，请员工完全退出 TDHarness 再打开，然后你再调一次 `permissions` 确认。

不要让员工把密码告诉你。员工不想开就停，不要绕。

## 2. 工具

工具名都是 `mcp__mac__<名字>`：

- `see`：截图并标出可点的元素（`app_target` 写应用名，如 `剪映专业版`）。`inspect_ui`：只读界面结构，不截图，更快。
- `click` / `type` / `press`（按键、快捷键）/ `scroll` / `drag` / `move`：动作。能按元素编号点就不要按坐标点。
- `app`（启动、退出、列出）、`window`（移动、调整、切换窗口）、`menu`（点菜单栏）、`dialog`（处理弹窗）。
- `sleep` / `verify_state`：等待、核对状态。

没有 `agent` / `analyze` / `browser`。点不了系统密码框。每次工具调用 60 秒上限，长操作拆成多步。

## 3. 每一步的规矩

1. 动作前先 `see` 或 `inspect_ui` 看当前状态，动作后再看一次，确认变了、变对了。
2. 点错了：`press` 发 `cmd+z` 撤回，再看一次。连续两次点不准就停下告诉员工，不要乱试。
3. 会改文件或发出去的动作先问员工，得到「可以」再做：导出、保存覆盖、删除、发送消息、提交表单。
4. 员工自己正在用的窗口，切走之前说一声。不要读和本任务无关的聊天窗口内容。

## 4. 剪映专业版

- 剪映很可能是自绘界面：`inspect_ui` 读不出里面的按钮时，用 `see` 看画面，按坐标点。
- 剪辑本身（切、删、排轨道、字幕、配乐）走口播工具写草稿：更快，切点精确到帧。点界面只做草稿做不到的事：剪映在线素材和 AI 功能、打开草稿检查、播放、导出。
- 写某个草稿之前，这个草稿不能在剪映里开着（剪映保存时会覆盖外面的改动）。
- 时间线上用快捷键比拖鼠标准：`cmd+b` 分割，`q` 删播放头左边，`w` 删播放头右边，`delete` 删选中，空格播放/暂停，左右方向键逐帧，`cmd+z` 撤销。快捷键以剪映菜单里显示的为准。
- 导出：右上角「导出」。先读出导出设置给员工看，员工确认后再点最后的导出。导出要等，隔一会儿看进度，不要一直点。
