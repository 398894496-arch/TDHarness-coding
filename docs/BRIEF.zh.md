# 企业 Agent 工作台 —— 项目讲解

本页是**单独的中文讲解**，按客户评估口径写，不替代英文 [README](../README.md) / [PRODUCT.md](PRODUCT.md)。不含站点地址、主机名、花名册人名。

本 GitHub 仓库是 **coding 补丁树**（本地文件夹 + 你自己的模型 key）。下面截图是**公司交付工作台**实际打开的样子；`setup.sh` 不会装出登录、花名册、任务验收。两棵树不要混。

---

## 先定场：这不是聊天窗口

员工在**自己电脑**上打开客户端，用**公司账号**登录。Agent 在这台电脑上替他干活（改本机稿、跑本机命令、点已经打开的网页）。文件、对话、任务卡落在**客户自己的公司盘**上。

一句话：**员工出力，产出和经验沉在公司；公司定规则，工作台持续维护。** 模型只是一双手。

适合大约 **20–100 人**、已有岗位和验收习惯的公司。少于约 20 人、没人管花名册、或不愿把资料放在自己机器上的，不是这套的客户。

装得上要同时有：企业专用网（最低办公室局域网）、客户自己一台常开 Windows 主机（内存不低于 32G，当公司盘和模型出口）、一份有人维护的花名册。不是开通即用的 SaaS。

## 打开之后是什么

同一份客户端。看见什么跟**账号角色**走。

### 会话

![会话：个人 / 团队工作区](screenshots/01-session.jpg)

左侧 **会话 / 任务**。工作区分成 **个人** 和 **团队**。对话里描述要做的事，附文件，选本机权限档，选公司提供的模型。成品进本人格子。员工不用自己配厂商钥匙。额度按人记账。

### 任务

![任务卡：提交验收才算交卷](screenshots/04-tasks.jpg)

任务是业务主面。对话钉在卡上；窗口和新建文件挂在卡上。**提交验收**才算交卷，聊天里说做完了不算。验收四格按岗位推进（待审 → 待终审 → 已通过 / 已退回）。

### 同事与人员（设置里）

**同事**：角色、在线、最后登录、近七日本地估价（不是厂商账单）。**人员**：按部门编花名册，改角色和部门、停用、吊销令牌。吊销一个人立刻生效，不影响别人。

## 和常见方案差在哪一层

| 问法 | 发一把 Key | 企微 / 钉钉助手 | SaaS Copilot | 本产品 |
| --- | --- | --- | --- | --- |
| 资料在哪 | 散落 | IM / 厂商云 | 那家云 | 客户自己的公司盘 |
| 本机干活 | 看员工怎么接 | 基本不能 | 只在那一个软件里 | 文件、命令、已打开的网页 |
| 任务和验收 | 无 | 聊天里催 | 还在那个 SaaS 里 | 工作台里四格验收 |
| 出事只停一个人 | 往往换全公司钥匙 | IM 账号 | SaaS 账号 | 花名册点一下吊销 |

飞书 / 钉钉 / 企微继续说话。工作台是执行端，不重做一套聊天。

## 安全，如实说

钥匙不下发。额度按人可吊销。公司盘按人隔离做在系统权限上。Agent 仍拥有该员工在这台机器上的权限——不假装能防住员工本人。
