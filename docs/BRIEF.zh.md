# 企业 Agent 工作台 —— 项目讲解

本页是**单独的中文讲解**，按客户评估口径写，不替代英文 [README](../README.md) / [PRODUCT.md](PRODUCT.md)。不含站点地址、主机名、花名册人名；截图里的人名和任务都是演示数据。

**当前版本：2026.10.10**（每一版改了什么见 [更新说明](../CHANGELOG.md)）

## 交付方式：一键安装

| 谁 | 做什么 | 得到什么 |
| --- | --- | --- |
| 服务器（一台常开的 Windows，装一次） | 克隆本仓，管理员身份跑**一条命令** `scripts/setup-all.ps1` | 登录、种子管理员、花名册、模型网关、知识库和每晚整理任务、下载页，以及按这台服务器编译好的 Windows / Mac 客户端 |
| 员工（Windows） | 浏览器打开 `https://<服务器计算机名>.local:8443/`，点「下载 Windows 版」，双击 `TDHarness-Setup.exe` | 装到当前用户的 TDH 文件夹，桌面出现快捷方式，用花名册账号登录 |
| 员工（Mac） | 同一页点「下载 macOS 版」，解压后拖进「应用程序」 | 同一套工作台（Apple 芯片和 Intel 都支持） |
| 以后的更新 | 管理员在服务器上跑 `server\publish-site-update.ps1` | 员工下次打开客户端时提示更新；带签名校验，能增量就增量，断点续传 |

员工不碰补丁、Node 或命令行。服务器事先装好 Git（含 LFS）、Node 22+、Python 3 即可。

**为什么 GitHub 的 Release 里没有通用安装包**：每家的安装包里写着自己服务器的地址和这台服务器自己的更新签名钥匙，所以由装机脚本在服务器上现场编译。通用安装包不知道该去哪登录、该信谁发的更新。

**「补丁树」是什么意思**：只说明源码怎么挂在上游内核 DeepSeek Harness 上——`kernel.yml` 锁定上游版本，装机时从 npm 装上游、再打本仓的补丁，不复制一份上游代码。这是源码的组织方式，**不是交付形态**。

可选的 `setup.sh` 只装内核命令行，不起上面这套服务。下面截图是一键安装装出来的工作台。仓库里没有公司资料，也没有订阅钥匙。

**默认管理员：账号 `tdh`，密码 `12345678`。** 装完打开桌面快捷方式，用这个账号登录。

## 先定场：这不是聊天窗口

员工在**自己电脑**上打开客户端，用**公司账号**登录。Agent 在这台电脑上替他干活（改本机稿、跑本机命令、操作浏览器里的网页）。文件、对话、任务卡落在**客户自己的公司盘**上。

一句话：**员工出力，产出和经验沉在公司；公司定规则，工作台持续维护。** 模型只是一双手。

适合大约 **20–100 人**、已有岗位和验收习惯的公司。少于约 20 人、没人管花名册、或不愿把资料放在自己机器上的，不是这套的客户。

装得上要同时有：企业专用网（最低办公室局域网）、客户自己一台常开 Windows 主机（内存不低于 32G，当公司盘、知识库和模型出口）、一份有人维护的花名册。不是开通即用的 SaaS。

## 打开之后是什么

同一份客户端（Windows 和 Mac 都有，Mac 支持 Apple 芯片和 Intel）。看见什么跟**账号角色**走。

### 会话

![会话：个人 / 团队工作区](screenshots/01-session.jpg)

左侧 **会话 / 任务**。工作区分成 **个人** 和 **团队**，对话存在公司盘上自己的工位里，换电脑登录还在。对话里描述要做的事，附文件，选本机权限档，再选设置里已经保存的模型。模型的钥匙和订阅都在服务器上（管理员在设置 → 模型里填），员工电脑上没有；员工端登录后自动列出服务器能调的模型，默认模型由服务器统一设定。钥匙不进仓库。额度按人记账。

### 任务

![任务：卡片列表，点开就带着任务开工](screenshots/04-tasks.jpg)

任务是业务主面。每张卡写着状态和负责人（待审批 / 进行中）。点开一张卡，对话框里自动带上「开始处理任务卡……」，这次对话就钉在这张卡上。交付物放公司盘。**提交验收**才算交卷，聊天里说做完了不算。验收按岗位推进（待审 → 待终审 → 已通过 / 已退回）。

### 同事与人员（设置里）

![同事：在线、角色、近七日用量](screenshots/02-colleagues.jpg)

**同事**：角色、在线、最后登录、近七日 token 用量（来自服务器网关，不是厂商账单）。

![人员：按部门管花名册](screenshots/03-personnel.jpg)

**人员**：按部门编花名册，改角色和部门、强制重新登录、停用、删除。强制重新登录只是让这个人重新输一次账号密码；停用会让他登不上，模型、联网搜索、生图、知识库检索和公司共享盘在下一次请求就全部停掉（每人有自己的共享盘账号，停用就关掉它），不影响别人；停用之后可以**删除**账号：从花名册消失、密码作废、这个登录名不再发放，个人文件夹留在公司盘上不删。种子管理员不能停用或删除。

## 十月新增

- **企业知识库，每天自动长。** 服务器每天 00:15 读当天所有人的对话，写证据层、每人每天一页蒸馏、收集纠错。员工在工作台里问「之前做过没有」，就是查这里。检索只认登录令牌：没登录、令牌被吊销、人被停用都查不到，填个名字冒充别人也没用；每次检索记一行谁查的、查到几条，不记问题原文。目前花名册里的人都能看全库，按部门分权限还没定。
- **联网搜索走公司网关。** 中文先走国内引擎（必应中国、360）加 Exa，GitHub、B 站、YouTube 有专门通道。以 `深搜 ` 开头的问题交给 Grok 带出处检索，在后台继续查，同一个问题再问一次就取到结果。
- **浏览器操作。** 客户端自带 OpenCLI 和它的 Chrome 扩展。第一次需要操作浏览器时，AI 先检查扩展装没装，没装就一步一步带员工装好（每次只说一步，等员工说做完了再说下一步）。需要登录的网站由员工自己在浏览器里登录，AI 不问密码。
- **生成的图片和视频，对话里直接看、直接下载。** AI 交付的图片在对话里直接显示（点开看大图），视频直接能播放；每个交付的文件旁边都有「下载」按钮，一点就存到自己电脑。右侧边栏的文件预览也有同样的下载按钮。
- **桌面软件操作（Windows / Mac）。** Windows 客户端自带 Windows-MCP，Mac 客户端自带 Peekaboo，AI 能看窗口、点按钮、打字、滚动、拖动、按快捷键，操作剪映这类桌面软件。导出、覆盖、删除、发送之前先问员工。剪映是自绘界面，只能看截图点，所以剪辑本身仍走口播工具直接写草稿（切点精确到帧），界面只用来做剪映独有的在线功能、检查和导出。Mac 第一次用时要在「系统设置」里开「辅助功能」和「屏幕录制」两项权限，由 AI 一步一步带着开。
- **长对话不会撑爆。** 上下文到模型窗口的 80% 自动压缩（Grok 是 50 万里的 40 万），厂商报「太长」时也会压缩后重试；`/compact` 可以手动压。已在 Grok 真实上限下验证过两条路径。
- **口播剪辑（可选装）。** 服务器上装 `server\koubo\install.ps1` 后，AI 能把一条录音剪成剪映草稿：对齐、转写、分清出镜人和镜头外的声音、剪掉口误、防抖、字幕和版式、配乐。同一条素材能出完整版和多个短版。

## 和常见方案差在哪一层

| 问法 | 发一把 Key | 企微 / 钉钉助手 | SaaS Copilot | 本产品 |
| --- | --- | --- | --- | --- |
| 资料在哪 | 散落 | IM / 厂商云 | 那家云 | 客户自己的公司盘 |
| 本机干活 | 看员工怎么接 | 基本不能 | 只在那一个软件里 | 文件、命令、浏览器里的网页 |
| 经验能不能沉下来 | 不能 | 聊天记录翻不到 | 在那家云里 | 每天蒸馏进自己的知识库 |
| 任务和验收 | 无 | 聊天里催 | 还在那个 SaaS 里 | 工作台里任务卡加验收 |
| 出事只停一个人 | 往往换全公司钥匙 | IM 账号 | SaaS 账号 | 花名册点一下停用 / 吊销 |

飞书 / 钉钉 / 企微继续说话。工作台是执行端，不重做一套聊天。

## 安全，如实说

钥匙不下发。额度按人可吊销。公司盘按人隔离做在系统权限上。知识库检索只认登录令牌，停用即失效。Agent 仍拥有该员工在这台机器上的权限——不假装能防住员工本人。
